Request lifecycle

  1. Physician opens the chart and asks the panel a question (or requests the pre-visit snapshot).
  2. Panel obtains a SMART-on-FHIR token from OpenEMR's OAuth2 server, bound to the logged-in user and the open patient.
  3. Panel calls /chat with the token and a fresh correlation ID that follows the request everywhere.
  4. Agent loop plans and calls read-only tools against OpenEMR's FHIR API using the user's token — the agent has no database credentials.
  5. OpenEMR's ACL + scope enforcement runs on every read, exactly as for any API client.
  6. LLM synthesis (BAA-covered; minimum-necessary PHI; tiered models).
  7. Draft + tool results pass through the verification layer: citation check, numeric check, clinical-rule flags — fail closed.
  8. Verified, cited response streams back to the panel; citations deep-link to source records.
  9. Invocation is audit-logged in OpenEMR (9a — the agent POSTs to the co-pilot module's audit-bridge endpoint, which calls EventAuditLogger in-process; FHIR reads in step 4 are already audited natively) and fully traced in LangSmith (9b), joined by the correlation ID. Audit delivery failure alerts but doesn't block the response — the trace preserves reconstructability.

Trust boundaries

  • ① Browser ↔ OpenEMR — existing session authentication, untouched.
  • ② Agent service ↔ OpenEMR — OAuth per request; the requesting user's token on every FHIR call; no standing credentials, no direct DB access. Authorization is inherited from the EMR's ACL and scopes, never re-implemented.
  • ③ Agent ↔ external services — BAA covers PHI at the LLM provider and LangSmith; minimum-necessary applies anyway (only the open patient's data; trace masking).

Known limitation (stated, not hidden)

  • OpenEMR's ACL is role-based, not panel-based — any chart-access role can open any chart. The agent inherits exactly that boundary: it does not widen the aperture, and misuse is a detective control (every access audited). Preventive panel scoping is roadmap.

Design invariants & targets

  • Read-only: zero write access to the EMR in v1 — collapses blast radius and most prompt-injection escalation paths.
  • Fail closed: a claim citing an unknown resource ID is stripped; a response that can't be verified says so and links to source records.
  • Coverage disclosure: a failed tool produces "labs unavailable," never a silently narrower summary.
  • Latency targets (pending load tests): first token < 3s · snapshot < 10s · follow-ups < 5s · p95 < 15s.
  • Cost: ≈ $0.02–0.10 per interaction; ≈ $1–2 per physician per day at 20 patients.
  • Traceability: every capability maps to a use case in USER.md (UC-1 snapshot · UC-2 follow-ups · UC-3 interval change · UC-4 coverage/absence).
