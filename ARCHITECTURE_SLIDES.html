OpenEMR fork · Architecture story

Clinical Co-Pilot

A chart-embedded agent that answers “what do I need to know about this patient right now?” — in seconds, with every claim cited.

Source: ARCHITECTURE.md · AUDIT.md · USER.md

The moment it serves

90 seconds between patients

Pre-visit review, chart already open. No new app, no new login, no context switch.

Target user, workflow & use cases: USER.md

System overview

A thin module + a separate agent service

rejected: in-process PHP agent  long LLM calls pin Apache workers · weak agent ecosystem · no clean trust boundary

Trust boundary №1

Authorization is inherited, not re-implemented

A nurse’s token sees what a nurse sees.

Known limit, stated up front: OpenEMR’s ACL is role-based, not panel-based — the agent inherits exactly that boundary. It widens nothing; it narrows nothing.

Trust boundary №2

The agent is read-only

A read-only agent can produce a bad summary. A writing agent can corrupt a chart. Zero write tools in v1 — which also defuses prompt injection: instructions smuggled into a note have no write tools to escalate into.

6 tools · all read write access

Trust is the product

Every claim cites a record — and a machine checks it

Hot path catches grounding

Fabricated or uncited claims cannot ship. Plus rule-based CDS: drug-interaction flags from the EMR’s own engine — and uncoded meds are flagged “interaction check unavailable,” never silently passed.

Not entailment — by design

A claim can cite a real lab and misstate it. That class is measured by an offline LLM-judge eval — an in-path judge doubles latency and adds a second model to trust.

Latency by design

One parallel snapshot, then depth on demand

Design targets, not measurements — validated under load before promised. Plus: streaming, model tiering (fast tier routes, strong tier writes), and partial results that say what’s missing.

What the code audit changed

The latency floor isn’t FHIR — it’s the bootstrap

The FHIR layer itself is single-query, not N+1 (BaseService::search()). Findings: AUDIT.md §2

Governing invariant

The physician always knows what the agent did not check.

A summary that omits a section must be distinguishable from one that verified the section is empty.

🧪 One tool fails (labs)

Answer with the rest + banner: “labs unavailable — covers meds, problems, allergies.” Never silently narrower.

🔌 LLM down or slow

Non-AI fallback: the panel renders a plain structured snapshot straight from FHIR. No model needed to show a med list.

🛑 Verification fails

Fail closed. Strip or block, then “couldn’t verify — view source records” with deep links.

📭 Empty or thin record

Stated affirmatively: “no encounters on file since 2023.” Absence of data is clinical information.

Malformed model output: Pydantic-validated at every step → one retry → fallback.

Accountability

Two mechanisms, one trail — joined by a correlation ID

If the audit POST fails

Fail open, with alarm. Service logs + EMR row are the durable record; the response isn’t blocked.

Traces are not the audit

SaaS trace retention ≪ HIPAA’s six-year horizon. The trace is a disposable debugging aid — which is what keeps it swappable.

Observability

Vendor-neutral by construction

OTel spans only eval cases live in git trace carries no compliance role  →  switching = exporter config + one adapter file. An adapter swap, not a re-architecture.

Dashboard & alerts ride the same spans: p95 > 15s · error rate > 5% · tool failures > 10% · cross-patient access anomaly — each alert documents its on-call response.

Evaluation

Every eval case guards a boundary

Invariants

Every claim cited · numbers match · failed tools disclosed · dosing/diagnosis requests refused.

Boundaries

Empty record · unreachable data categories (refuse, don’t fabricate) · injected documents · questions about a different patient.

Real data-quality traps from the audit

“No allergies recorded” ≠ “no allergies” · demo patient 2’s Lisinopril is active in one table, inactive in another — the agent must flag the conflict · 0000-00-00 renders as “unknown,” never date math.

Ground truth: synthetic patients only, where the right answer is known by construction. The suite is weighted toward cited-but-misstated claims — the class the hot path can’t catch.

Choices, with the road not taken

Five decisions that shaped everything

LLM
Claude, tiered self-hosted OSS
BAA-compatible, strong tool use; self-hosting’s ops cost unjustified in a one-week sprint.
Framework
minimal explicit loop LangGraph · multi-agent
One agent, ~6 tools: a loop I can fully explain beats a framework I’d debug under deadline.
Service
FastAPI + Pydantic PHP in-process
Non-blocking long calls, independent scaling, contracts at every tool boundary.
Data access
FHIR with the user’s token direct SQL
Inherits ACL, scopes, audit. SQL would move authorization into my code. Cost: an HTTP hop — paid for by the parallel snapshot.
Traces
LangSmith behind OTel Braintrust · Langfuse
BAA criterion tied; tiebreak on one-platform + zero ops. The design makes later switching deliberately cheap (§11).

Cost & scale outlook

Each 10× has one dominant problem

≈ $0.02–0.10 per interaction ≈ $1–2 per physician per day

Stated plainly

The defensible version is the one whose gaps are documented

No panel scoping

Inherited from OpenEMR — any chart-access role opens any chart. Detective controls now, with a cross-patient anomaly alert as the detector; panel + break-glass on the roadmap.

Grounding ≠ entailment

Hot path can’t catch cited-but-misstated claims. Measured offline; in-path check only if the rate justifies the latency.

Injection residual

Adversarial documents can still bias emphasis. Mitigated by evals — honestly not fully solved.

Targets unvalidated

Latency numbers are design targets until load testing (10/50 concurrent) lands.

One persona · data as found

Nurses and residents deferred (safe to add later via inherited auth). v1 reconciles meds across disagreeing tables and flags conflicts.

Three platform fixes gate the panel

Reflected-origin CORS, missing session regeneration, and MFA absent from the session guard — fixed before cross-origin exposure, session-cookie hardening alongside. Until then: same-origin module only.

One invariant to remember

The physician always knows what the agent did and what it did not check — and every claim points at a record.

Read-only · inherited authorization · deterministic verification · honest failure · swappable vendors
